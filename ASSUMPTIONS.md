# Assumptions – Walnut Folks Group Assessment

## 1. Account Management
- Each account has a unique ID generated by the application.
- An account name is required when creating an account.
- The initial balance defaults to `0` if not provided.
- The initial balance must be a valid, non-negative number.
- An account must exist before transactions can be performed on it.

## 2. Transaction Management
- The supported transaction types are `DEPOSIT` and `WITHDRAWAL`.
- Transaction amounts must be positive numbers.
- A deposit increases the account balance.
- A withdrawal decreases the account balance.
- Withdrawals are rejected if the account has insufficient funds.
- Each transaction requires a reference ID.
- A reference ID must be unique within the same account.
- Duplicate transaction references are rejected to prevent duplicate processing.
- Transactions update the account balance and create the transaction record within a database transaction.

## 3. Transaction History
- Transactions are returned in descending order of creation time, with the newest first.
- Transaction history supports pagination.
- The default page number is `1`.
- The default page size is `10`.
- The maximum permitted page size is `100`.

## 4. Validation and Error Handling
- Request data is validated before processing.
- Invalid request data returns an appropriate client error.
- Requests for nonexistent accounts return a not-found response.
- Insufficient funds return a client error.
- Duplicate transaction references return a conflict response.
- Unexpected server errors return a generic internal server error response.

## 5. Database and Technology
- PostgreSQL is used as the relational database.
- Prisma ORM is used for database operations.
- Database transactions are used to keep account balance updates and transaction records consistent.
- The application is implemented using Node.js, Express, and TypeScript.

## 6. Scope
- The assessment implements account creation, account retrieval, deposits, withdrawals, and paginated transaction history.
- Money transfers between accounts are not included in the current implementation.
- Authentication and authorization are outside the current implementation scope.
